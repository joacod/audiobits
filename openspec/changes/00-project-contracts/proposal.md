# Project contracts

## Why

The product direction needs an implementable boundary before creating a library
and interactive site. A public, step-scoped design makes lifecycle, recipe, and
distribution decisions reviewable without claiming a working product.

## What Changes

- Establish public repository instructions and a concise status-aware README.
- Design recipe v1, ownership, core sounds, site UX, and validation gates.
- Plan local package consumption and independent site/npm releases.
- Create bounded OpenSpec changes for Steps 01–06, with Chromium-first acceptance.

## Capabilities

### New Capabilities

None implemented. This is documentation and planning only; `.openspec.yaml`
sets `skip_specs: true`. Runtime behavioral deltas belong to subsequent changes.

### Modified Capabilities

None.

## Impact

Changes README, AGENTS.md, contributor design documents, and OpenSpec artifacts.
No dependencies, runtime, website, CI, publication, or deployment is implemented.
No original private handoff or other project's local paths are copied.
