# Product iteration roadmap

The dependency-free recipe/runtime foundation and private candidate are implemented.
Publication and deployment remain disabled. Ordinary changes need no formal
specification; architecture changes use the gate in [AGENTS.md](../AGENTS.md).

Verify and commit each coherent slice before advancing:

1. **API cleanup:** recipe-aware authoring types, rigorous unknown-input validation,
   experimental shared-delay status, simple first example and canonical docs.
2. **Sound model:** tactile click, gentle rejection, glass notification, whoosh,
   power-up, alongside confirmation, impact and thruster. Use existing primitives;
   automated properties and listening review remain separate acceptance evidence.
3. **Gallery foundation:** presentation metadata outside recipes, parameter-derived
   controls, shared playback lifecycle, validated edits and current copyable examples.
4. **Showcase:** purposeful interaction, visible procedural morphing, local-generation
   feedback, simple code and honest selected raw Web Audio comparisons.
5. **Release preparation:** final browser matrix, package rehearsal, docs and README.
   API freeze and acceptance need listening review and exact artifact evidence.
   Publication and deployment require separate explicit approval.

MCP, devtools UI, premium packs, registry, framework adapters, CLI, worklets, WASM,
sequencing, MIDI, recording, streaming, generalized effects, plugins and package
splitting wait for real requirements. Offline rendering/caching needs measured
benefit and an equivalence/ownership design. The [recipe study](recipe-study.md)
preserves abstraction pressure; sketches are not shipped capabilities.
